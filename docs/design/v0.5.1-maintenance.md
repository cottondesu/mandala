# v0.5.1 maintenance contract

Baseline: published v0.5.0, `dbb697e7ab79e31727202b4f2e67aa5c62f2ab48`.
The earlier maintenance prompt is unavailable in this chat. This contract is
reconstructed from the current request, baseline code and tests,
[batch design](v0.5.0-atomic-batch.md), and the
[independent audit](https://github.com/cottondesu/mandala/pull/6#issuecomment-6415765100).
It does not amend the published baseline or grant release approval.

## Preserved behavior

- State schema 1, existing state encoding and sorting, CLI and JSON schemas,
  resource limits, error codes, and single-writer assumptions remain unchanged.
- Batch validates input before loading state, applies operations to a copy,
  validates the final state, and saves at most once through the existing writer.
- Dry-run and semantic no-op never save. Input, operation, validation, and save
  failures preserve state bytes and mtime and produce no success output.
- Ordinary symlinks to regular input files remain accepted. Relative input paths
  resolve against the invocation directory, independently of `--project`.
- No dependencies, process locks, concurrent-write guarantees, exactly-once
  execution, state migration, tags, publication, or automatic merging are added.

## A. Input identity and special files

The audit identified Windows `os.Stat` results whose file IDs are loaded lazily
from the path during `os.SameFile`. The old different-path test does not reproduce
a replacement at the original path. Unix stat-before-open can still block if a
regular file becomes a FIFO before open.

Capture Windows identity from an open handle and compare it with the data handle
before reading. Retain the snapshot handle during comparison. Check regular-file
type on handles. Use nonblocking open on Unix to reject a FIFO replacement without
waiting for a writer. Tests must replace the same input path, verify rejection
before state changes, and preserve symlink compatibility. Document the exact
identity-snapshot boundary and any remaining trust requirements. Do not claim
content immutability against another process writing through an existing handle.

Required native Windows cases must run successfully on both CI toolchains.
Cross-compilation alone cannot satisfy this item.

## B. Output failure

Preserve Go's default SIGPIPE behavior. A returned stdout error reports `E_IO`
and exit 2. Unix SIGPIPE can terminate the process with no diagnostic; shells
commonly report 141. Either can occur after a successful save. There is no rollback
or automatic safe retry. Real-binary tests must observe SIGPIPE and committed
state, and verify dry-run state preservation. Existing returned-error coverage
remains required.

## C. JSON diagnostics

Reject `batch_version: 01` as malformed JSON rather than unsupported version 0.
Distinguish malformed numeric continuations from valid unsupported JSON numbers
such as 0, 2, 1.0, and 1e0. Preserve strict key/type/duplicate checks and unrelated
diagnostic precedence. Exercise both root-field orders and both Go toolchains.

## D. Native Windows save failure

Add an OS-level failure inside the real state writer, exercised through the real
CLI. Prove exit 2, empty stdout including `--json`, `E_IO`, unchanged state bytes
and mtime, and removal of temporary state files. Dry-run must succeed without
writing under the same injection. After removing the injected failure, apply must
succeed. Mock-only tests do not resolve MINOR-4. Windows cases must not silently
skip; the v0.5.0 exception does not apply to v0.5.1.

## E. Evidence collection

Collect raw stdout and stderr, actual command exit codes and argv, UTC start/end
times, the selected Go executable's exact version and OS/architecture, full Git
SHA, source cleanliness before/after, and SHA-256 log hashes. Produce
`manifest.json` and a derived `summary.md` outside the source checkout. Distinguish
success, failure, unexecuted checks, and interruption. Persist progress before
executing each command and refuse to overwrite a prior run. Dirty development
runs must not claim to validate an exact release candidate.

## Verification and decision

For Go 1.26 and 1.27, run ordinary, shuffled, and race-enabled tests, vet, build,
and `git diff --check`. Preserve the existing ten-job CI matrix. Inspect native
Windows logs for the new tests, their exact source SHA, and absence of skips.
Report A through E separately. Only all five PASS plus completed required CI
permits `READY FOR INDEPENDENT AUDIT`; otherwise report the evidenced blockers.
Independent audit and release authorization remain separate steps.
